# V1.3-D — Cloudflare + Reverse Proxy

## Repository audit

The application repository does not contain the NAS/Cloudflare runtime configuration. The reverse proxy is therefore a deployment concern, not part of `server.js`.

The application listens on the container port from `PORT` (default `8080`). On the NAS, the intended mapping is:

```text
NAS 8081 -> container 8080
```

`/health` is intentionally public for health checks. `/api/jobs` and the job-management endpoints require `X-API-Key`.

## Target architecture

```text
Internet
  |
  v
Cloudflare HTTPS
  |
  v
Synology Nginx :443
  |
  v
127.0.0.1:8081
  |
  v
Docker revo-qr-upload :8080
```

Do **not** publish NAS port `8081` directly to the Internet when Nginx/Cloudflare is in use.

## Cloudflare

Create/use the DNS record:

```text
Type: A (or CNAME according to the existing DNS setup)
Name: qr
Target: the existing public endpoint for the NAS
Proxy status: Proxied
```

Use HTTPS for the public hostname. Prefer Cloudflare SSL/TLS mode `Full (strict)` when the origin certificate is valid for the hostname.

## Synology Nginx

Use the example in:

```text
deploy/nginx/qr-upload.conf.example
```

The important routing rule is:

```text
qr.revolearning.online -> http://127.0.0.1:8081
```

Do not edit Synology's generated Nginx configuration blindly. Configure the reverse proxy through the NAS interface where possible, then validate the generated configuration.

## Upload size

The application defaults to `MAX_FILE_MB=100`. The reverse proxy must allow at least the same request size. The example therefore uses:

```text
client_max_body_size 100m
```

If the Cloudflare plan/route imposes a lower request limit, the effective public upload limit will be lower.

## API key boundary

The browser upload endpoint is `/api/upload` and intentionally does not require the internal job API key. The job-management endpoints do require:

```text
X-API-Key: <secret>
```

Never place the API key in the public URL, HTML, JavaScript, Git repository, or Cloudflare DNS record.

## Verification order

After configuring the NAS reverse proxy:

1. Verify locally: `curl -i http://127.0.0.1:8081/health`
2. Verify public HTTPS: `curl -i https://qr.revolearning.online/health`
3. Verify `/api/jobs` without a key returns `401`.
4. Verify `/api/jobs` with the real key returns `200`.
5. Upload a small PDF through the public UI.

Do not expose the real API key in screenshots, logs, shell history, Git, or browser-side JavaScript.
